# To do

- **Metered networks on the desktop:** "Sync on metered networks" exists only on Android. The desktop portal's network monitor, which src/infrastructure/network_monitor.rs already follows for Offline, also answers `GetMetered`. Report it into `Conditions::metered` (src/services/power.rs) like `Bridge.watchNetwork` does on Android, and show the switch in Preferences on the desktop too. Without a portal, assume unmetered.
- **Android: release the fix for the window that didn't come back after the screen was off:** Started with the screen off, Android stopped the activity before it had a native window; Syncative closed its window while iced still deferred creating it, and opened a new one at the next start. Both were created on the one native window, the second surface failed with `ERROR_NATIVE_WINDOW_IN_USE_KHR`, and every later activity panicked with `RecreationAttempt`. Fixed in the iced fork (`android-0.14`, e8c6543c8: a close drops the deferred `CreateWindow`) and tested on the Pixel 4a; it ships with the next iced_android release ([release.md](packaging/release.md#the-android-forks)).
- **Log lines without a length limit:** The folder logs (200 lines each, `MAX_LOG_LINES`) and the captured log (4096 lines, `RING_CAPACITY` in src/infrastructure/stderr_capture.rs) are bounded in lines but not in line length. In practice lines stay at a few hundred characters; cutting them at about 2000 would bound the memory for good.
- **AppStream metainfo:** ship `usr/share/metainfo/io.github.santuzius.syncative.metainfo.xml` in the AppImage with screenshots from `doc/img/`, then `/retest` the AppImageHub PR ([release.md](packaging/release.md#appimagehub)).
- **Tray icon appearing later:** Without a system tray at start, Syncative opens its window. Check whether it should add the tray icon once a StatusNotifierWatcher appears later (e.g. the GNOME AppIndicator extension enabled while it runs).
