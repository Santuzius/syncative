- **Log lines without a length limit:** The folder logs (200 lines each, `MAX_LOG_LINES`) and the captured log (4096 lines, `RING_CAPACITY` in src/infrastructure/stderr_capture.rs) are bounded in lines but not in line length. In practice lines stay at a few hundred characters; cutting them at about 2000 would bound the memory for good.
- **AppStream metainfo:** ship `usr/share/metainfo/io.github.santuzius.syncative.metainfo.xml` in the AppImage with screenshots from `doc/img/`, then `/retest` the AppImageHub PR ([release.md](packaging/release.md#appimagehub)).
- **Tray icon appearing later:** Without a system tray at start, Syncative opens its window. Check whether it should add the tray icon once a StatusNotifierWatcher appears later (e.g. the GNOME AppIndicator extension enabled while it runs).
- **MEGA:** requested in issue 2; a beta provider is in progress, see [mega.md](providers/mega.md).
- **Proton's new cryptography:** The [Drive SDK's README](https://github.com/ProtonDriveApps/sdk#current-status) announces a new cryptographic model for the end of 2026 or early 2027, after which clients that only know the old one stop working. Syncative's Drive client (`src/go/proton/drive`) builds on go-proton-api, whose Drive files have not changed since 2023 while Proton's own Drive apps are moving to the SDK. Around the turn of the year, check whether go-proton-api follows; if not, the Drive client has to follow the SDK (C# and TypeScript, without sign-in and session handling).
- **Proton session in Go:** Once the point above is settled and the Drive client stays in Go, the session could move from `src/infrastructure/proton/` into the rclone backend, kept in the encrypted rclone config like other remotes' OAuth tokens: the backend resumes it on first use and writes renewed tokens back, so Proton becomes a plain rclone remote on the Rust side. Sessions saved in the keyring would move into the config once. That also ends the Proton client's direct call into the network drives: today a new sign-in unmounts the remote's drives itself before logging out the session it replaces (`bind` in `src/infrastructure/proton/client.rs`), bypassing the engine; with the session in the backend, that order has to hold there.
